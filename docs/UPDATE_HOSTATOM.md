# อัปเดตเว็บบน Hostatom แบบง่าย — v1.0 → v1.1

เว็บที่ติดตั้งอยู่: https://90thsisat.tonpradoo.com
โฟลเดอร์แอป: 90thsisat.tonpradoo.com
โฟลเดอร์ข้อมูล: 90thsisat-storage

## รุ่นนี้เปลี่ยนอะไร

- รองรับจอ 390×844, iPad 768×832, 810×1080, 820×1180 และแนวนอน 1024×768; เมนูล่างเผื่อ safe area และหน้า login เลื่อนภายในได้
- กรองข้อมูล API ด้วยรายการ field ที่อนุญาต ทั้ง GET, ผลการแก้ไข และ export ตามสิทธิ์เดิม
- ลูกค้าเห็นเฉพาะรายการตนเอง; เจ้าหน้าที่เห็นสถานะร่วมกันตามที่ต้องใช้ ส่วนสลิป/ข้อมูลแพ้อาหาร/รหัสตั๋วแยกสิทธิ์
- ไฟล์สลิปใหม่เข้ารหัส AES-256-GCM ก่อนบันทึก; มีคำสั่งย้ายสลิปเก่าโดยไม่เปลี่ยนออเดอร์
- จำกัดการลอง login, เพิ่ม CSP/HSTS, ไม่ cache API ส่วนตัว และไม่เผย production source maps

## 1. สำรองก่อน

ทำช่วงที่ผู้ทดสอบหยุดใช้งานชั่วคราว

1. Plesk → Databases → tonpra_reunion_v1 → Export dump แล้วดาวน์โหลดเก็บไว้
2. Files → Home directory → สำรองโฟลเดอร์ 90thsisat-storage ทั้งโฟลเดอร์ รวมไฟล์ที่ขึ้นต้นด้วยจุด
3. เก็บสำเนา .env.local จากโฟลเดอร์แอปไว้เป็นส่วนตัว
4. จด tag รุ่นเดิม v1.0.0-demo สำหรับย้อนโค้ด

เก็บ backup นอก public/ และไม่ใส่ Git การสลับ branch ไม่ได้ย้อนฐานข้อมูลหรือสลิปให้

## 2. อัปโหลดโค้ดใหม่

ใช้ ZIP ของ tag **v1.1.0-demo** หรือ branch **release/v1.1-security-tablet** จาก GitHub:

https://github.com/tonpradooenter/90threunion_02/tree/release/v1.1-security-tablet

Files → เข้า 90thsisat.tonpradoo.com → Upload ZIP → Archive → Extract Files → อนุญาตเขียนทับไฟล์ source เดิม

หลังแตก package.json และ app.cjs ต้องอยู่ระดับเดิม ไม่ซ้อนโฟลเดอร์ตามชื่อ ZIP ถ้าใช้ GitHub Download ZIP ให้ย้ายไฟล์ source ภายในโฟลเดอร์ที่แตกออกมาให้อยู่ตรง Application Root ก่อน

**คง .env.local และ 90thsisat-storage เดิมไว้** ZIP ที่ให้เป็น source ล้วน ไม่มีข้อมูลลูกค้าหรือรหัสจริง ไม่ต้องสร้างฐานข้อมูลใหม่ ไม่ต้องเปลี่ยน DNS หรือค่าของ WordPress

## 3. รันคำสั่งทีละรายการ

Node.js ของ 90thsisat.tonpradoo.com → Run Node.js commands → เลือก Node 24 และ npm

```text
ci --include=dev
run db:check
run security:migrate
run build
```

รอแต่ละคำสั่งสำเร็จก่อนเริ่มถัดไป

- db:check แสดงจำนวนบัญชี/ออเดอร์เดิม ไม่ reset ข้อมูล
- security:migrate เข้ารหัสสลิปเก่าที่ออเดอร์อ้างถึง และตรวจไฟล์ที่เข้ารหัสแล้ว รันซ้ำได้
- หากไม่มีสลิปเก่าจะรายงาน 0 ไฟล์ ซึ่งปกติ
- ยังไม่ต้องรัน db:setup สำหรับการอัปเดตนี้ เพราะ schema ไม่เปลี่ยน

กลับ Dashboard → **Restart App** หลัง build สำเร็จ

## 4. ตรวจรุ่น

เปิด https://90thsisat.tonpradoo.com/api/health ต้องได้:

```json
{"status":"ok","version":"1.1.0"}
```

รีเฟรชหน้าเว็บด้วย Ctrl+Shift+R; บน iPad ปิดแท็บเดิมแล้วเปิดใหม่ ตรวจเมนูล่าง การเปิด login และออเดอร์เดิม

ลองเปิดสลิปด้วย customer เจ้าของรายการหรือ finance; บัญชีอื่นต้องเปิดไม่ได้ และลองตั๋วที่ใช้แล้วซ้ำต้องถูกปฏิเสธ

## 5. เก็บกุญแจสลิปไว้

ระบบสร้างกุญแจสุ่มครั้งเดียวที่:

```text
90thsisat-storage/.security/slip-v1.key
```

ไฟล์นี้อยู่นอก Document Root ไม่ถูกส่งให้ browser และไม่อยู่ใน source ZIP ต้องสำรองหลังการย้ายสลิปและหลังเริ่มใช้งานรุ่นนี้ **ห้ามลบหรือสร้างกุญแจใหม่ทับ** เพราะสลิปเดิมจะถอดรหัสไม่ได้

เก็บสำเนากุญแจแยกจากสำเนาไฟล์สลิปและป้องกันการเข้าถึง ใน shared hosting กุญแจยังต้องอ่านได้โดย process ของแอป การเข้ารหัสนี้ไม่ป้องกันผู้โจมตีที่ยึดทั้งบัญชีโฮสต์และกุญแจได้แล้ว

สำหรับผู้ดูแลที่ใช้ secret manager สามารถกำหนด SLIP_ENCRYPTION_KEY เป็น hex 64 ตัวแทนไฟล์ได้ แต่ต้องตั้งก่อนเข้ารหัสครั้งแรกและเก็บค่าเดิมตลอด รุ่นนี้ไม่หมุนกุญแจอัตโนมัติ

## ย้อนกลับเมื่อพบปัญหา

1. หยุดให้ผู้ทดสอบทำรายการระหว่างกู้คืน
2. คืน source จาก v1.0.0-demo แล้วติดตั้ง/build ใหม่ตามเดิม
3. **ถ้าย้ายสลิปเป็นรูปแบบเข้ารหัสแล้ว ต้องกู้ storage สำรองก่อนอัปเดตด้วย** รุ่น v1.0 อ่านสลิปที่เข้ารหัสแบบใหม่ไม่ได้
4. กู้ฐานข้อมูลจาก backup คู่เดียวกันหากต้องย้อนรายการที่เกิดหลังอัปเดต
5. Restart App และตรวจข้อมูลอีกครั้ง

หากมีรายการใหม่หลังอัปเดต การกู้ backup จะย้อนรายการเหล่านั้นด้วย ควรประสานผู้รับผิดชอบก่อนกู้ข้อมูล

## การอัปเดตรุ่นถัดไป

เลือก tag ใหม่ → อ่าน migration notes → backup DB/storage/key/.env.local → อัปโหลด source ทับ → ci --include=dev → รัน migration ที่รุ่นนั้นระบุ → build → Restart App → ตรวจ health และรายการเดิม

ไม่ลบฐานหรือ storage เพียงเพื่ออัปเดตหน้าเว็บ
