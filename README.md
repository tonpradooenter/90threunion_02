# SISAT 90 Reunion — Local Demo

เว็บสาธิตงานคืนสู่เหย้า 90 ปี วิทยาลัยเทคนิคศรีสะเกษ สำหรับนำเสนอและลองขั้นตอน ใช้ **Next.js + TypeScript + PostgreSQL** ทั้งบนคอมเครื่องนี้และเป็นแนวทางเดียวกับ Linux ภายหลัง

> **ข้อมูลสาธิตเท่านั้น** ราคา วันงาน สินค้า ภาพประกอบ และข้อมูลรับชำระเงินยังไม่ใช่ข้อมูลที่ประกาศใช้งานจริง ไม่ควรเปิด Demo นี้รับเงินหรือข้อมูลลูกค้าจริงบนอินเทอร์เน็ต

## เปิดบนคอมพิวเตอร์ Windows

เครื่องนี้มี PostgreSQL 17 แบบ portable อยู่ใน `tmp/postgres-17/` และฐานข้อมูลสาธิตอยู่ใน `tmp/pgdata/` แล้ว ทั้งสองตำแหน่งถูกละเว้นจาก Git เพื่อไม่ให้ข้อมูลหรือรหัสผ่านหลุดไปกับ branch ต้องมี Node.js 20.9 หรือใหม่กว่า

เปิด PowerShell หน้าต่างแรกในโฟลเดอร์นี้แล้วสั่ง:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-local-db.ps1
npm.cmd run db:setup
npm.cmd run db:backfill
npm.cmd run db:check
```

เปิด PowerShell หน้าต่างที่สองแล้วสั่งเว็บด้วยตนเอง:

```powershell
npm.cmd install
npm.cmd run dev
```

เข้า `http://127.0.0.1:3000` แล้วใช้บัญชีด้านล่าง หยุดเว็บด้วย `Ctrl+C` ในหน้าต่างที่สอง และเมื่อเลิกทดสอบฐานข้อมูลให้สั่ง `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop-local-db.ps1` ในหน้าต่างแรก หากหน้าเว็บค้างหลังแก้โค้ด ให้หยุดและเปิดใหม่ แล้วกด `Ctrl+F5`

`npm.cmd run db:setup` ใช้สร้าง schema และนำเข้าข้อมูล `data/demo.json` เมื่อฐานข้อมูลยังว่างเท่านั้น; คำสั่งนี้จะไม่ทับข้อมูลในฐานข้อมูลที่มีบัญชีหรือคำสั่งซื้อแล้ว `.env.local` เก็บ `DATABASE_URL` ของเครื่องนี้และไม่อยู่ใน Git หากย้ายไปเครื่องอื่นให้ติดตั้ง PostgreSQL, สร้างฐานข้อมูล, ตั้ง `DATABASE_URL` ใหม่ แล้วรัน `db:setup` และ `db:check` โดยไม่ต้องเปลี่ยนโค้ดเว็บ

ผู้จัดทำยังไม่ได้เปิดเว็บเซิร์ฟเวอร์ให้ ผู้ใช้เป็นผู้สั่งรันเองตามที่ตกลงกัน
## บัญชีทดลอง

ทุกบัญชีใช้รหัสผ่าน `Demo@1234` และเลือกกรอกชื่อผู้ใช้อัตโนมัติได้จากหน้าล็อกอิน

| ชื่อผู้ใช้ | บทบาท | สิ่งที่ลองทำได้ |
| --- | --- | --- |
| `customer` | ลูกค้า | จองโต๊ะ ซื้อสินค้า ส่งสลิป ดูตั๋ว |
| `superadmin` | ผู้ดูแลระบบหลัก | ดูทุกฝ่าย มอบหมายบทบาท ดูประวัติ |
| `tableadmin` | ฝ่ายโต๊ะจีน + ฝ่ายของที่ระลึก | เปลี่ยนราคาโซน จัดการสินค้า และช่วยลูกค้าสั่งจองทั้งสองประเภท |
| `shopadmin` | ฝ่ายของที่ระลึก | เพิ่ม/แก้ไข/ปิดสินค้า เปลี่ยนรูปและสต็อก |
| `finance` | ฝ่ายการเงิน | ดูสลิป อนุมัติ หรือขอสลิปใหม่ |
| `gate` | ฝ่ายหน้างาน | ตรวจรหัสตั๋วและใบรับสินค้า |

สมัครบัญชีลูกค้าใหม่ด้วยชื่อผู้ใช้และรหัสผ่านได้ด้วย ปุ่ม Google และ LINE เป็นเพียงตัวอย่างหน้าจอ ยังไม่เชื่อมบริการจริง

เมื่อเจ้าหน้าที่ล็อกอิน เมนูบนเว็บจะแสดงเฉพาะหน้าหลังบ้านตามสิทธิ์ที่ได้รับ เช่น `finance` เห็นภาพรวมและตรวจสลิป ส่วนเมนูจองโต๊ะ ร้านค้า และ “คำสั่งซื้อของฉัน” เป็นของบัญชีลูกค้าเท่านั้น เจ้าหน้าที่หลายบทบาทจะเห็นเมนูของทุกฝ่ายที่ได้รับสิทธิ์

เว็บแคมจะเริ่มทำงานต่อเมื่อกดปุ่มเปิดกล้อง และหยุดเมื่อสแกนสำเร็จ ปิดกล้อง หรือออกจากหน้านั้น การใช้งานบนคอมเครื่องนี้ผ่าน `http://127.0.0.1:3000` รองรับการขอสิทธิ์กล้องในเบราว์เซอร์ทั่วไป หากไม่มีกล้องหรือไม่อนุญาตให้ใช้กล้อง ยังสามารถกรอกรหัสเพื่อตรวจได้

## ลำดับสาธิตที่แนะนำ

1. เข้าเว็บในฐานะผู้ชม ดูหน้าแรก ผัง A–J โซนละ 60 โต๊ะ และร้านสินค้า
2. ล็อกอินเป็น `customer` เลือกโต๊ะว่าง กำหนดชุดอาหารและข้อจำกัดอาหาร แล้วกดยืนยัน
3. เปิด “คำสั่งซื้อของฉัน” และอัปโหลดภาพ PNG/JPG/WebP ไม่เกิน 3 รูป รูปละไม่เกิน 5 MB เป็นสลิปทดลอง
4. ออกจากระบบ เข้า `finance` ไปที่ “ตรวจสลิป” ดูภาพ แล้วกดอนุมัติหรือขอแก้ไขพร้อมหมายเหตุ
5. กลับเข้า `customer` เปิดบัตรผ่านพร้อม QR 8 ใบต่อโต๊ะ หรือใบรับสินค้าของคำสั่งซื้อสินค้า
6. เข้า `gate` กด “เปิดกล้องสแกน QR” แล้วส่อง QR บนบัตรผ่าน หรือกรอกรหัสใต้ QR เพื่อลองตรวจสิทธิ์และการป้องกันใช้ซ้ำ
7. เข้า `tableadmin` ไปที่ “ช่วยลูกค้าสั่งจอง” เลือกบัญชี `customer` แล้วลองเพิ่ม/ลดโต๊ะหรือจำนวนเสื้อในรายการตัวอย่างที่เจ้าหน้าที่รับทางโทรศัพท์/LINE
8. เข้า `superadmin` เพื่อมอบหมายหลายบทบาทให้เจ้าหน้าที่คนเดียว และเข้า `shopadmin` เพื่อแก้สินค้า รูป ราคา หรือสต็อก

บัญชี `customer` มีออเดอร์ตัวอย่าง 4 รายการ: โต๊ะที่อนุมัติแล้ว 1 รายการ, สินค้าที่อนุมัติแล้ว 1 รายการ และร่างที่เจ้าหน้าที่ช่วยบันทึกอีก 2 รายการ ร่างแก้ไขหรือยกเลิกได้จากหน้าช่วยลูกค้า ส่วนรายการที่ส่งตรวจ/อนุมัติแล้วล็อกการแก้ไขเพื่อไม่ให้ยอดชำระและตั๋วคลาดเคลื่อน เมื่อลูกค้าล็อกอินจะเห็นรายการที่เจ้าหน้าที่ทำให้และอัปโหลดสลิปจากบัญชีตนเองได้

คำสั่งซื้อใหม่ที่ลูกค้าจองเองกันโต๊ะหรือสินค้าไว้ 60 นาที (แยกค่ากัน) ส่วนที่เจ้าหน้าที่ช่วยบันทึกเริ่มต้น 24 ชั่วโมง (แยกค่ากัน) และคำขอสลิปใหม่เริ่มต้น 24 ชั่วโมง ทั้งหมดปรับได้ในเมนู “ตั้งค่าเว็บ” ของ superadmin; ออเดอร์ตัวอย่างเดิมอาจยังคงกำหนดเวลาเดิม เมื่อหมดเวลา ระบบคืนสิทธิ์จองและแสดงข้อความให้ลูกค้าเลือกใหม่ ฝ่ายการเงินต้องตรวจยอดเงินจริงเองในระบบจริง Demo ไม่มีระบบอ่านสลิปด้วย AI หรือเชื่อมธนาคาร


## ตั้งค่าเว็บและส่งออกข้อมูล

`superadmin` เปิดหลังบ้าน → “ตั้งค่าเว็บ” เพื่อปรับเวลาส่งสลิป 5 กรณีแยกกัน: ลูกค้าจองโต๊ะ, ลูกค้าสั่งสินค้า, เจ้าหน้าที่ช่วยจองโต๊ะ, เจ้าหน้าที่ช่วยสั่งสินค้า และการส่งสลิปใหม่หลังถูกตีกลับ เลือกหน่วยนาที/ชั่วโมง/วันได้ สูงสุด 30 วัน การเปลี่ยนค่าส่งผลกับออเดอร์ใหม่; ออเดอร์เดิมใช้กำหนดเวลาที่บันทึกไว้แล้ว เมื่อส่งสลิปแล้วสิทธิ์จองคงอยู่ระหว่างการเงินตรวจสอบ ระบบจะปล่อยสิทธิ์เมื่อหมดเวลาที่ยังไม่ได้ส่งสลิปหรือหมดเวลาส่งสลิปใหม่

หน้าเดียวกันตั้งเวลาปิด session เมื่อไม่มีการใช้งานได้ เริ่มต้น 300 วินาที การเคลื่อนไหวที่นับคือการคลิก แตะ กดแป้นพิมพ์ หรือเลื่อนหน้า ระบบเตือนใน 60 วินาทีสุดท้ายและตรวจเวลาฝั่งเซิร์ฟเวอร์ด้วย การปิด session มีไว้ลดความเสี่ยงที่เปิดบัญชีค้างบนเครื่องร่วมกัน; ไม่ใช่เครื่องมือจำกัดจำนวนผู้ใช้หรือ traffic

ส่วนภาพลักษณ์หน้า Home เปลี่ยนโลโก้งาน ตรา สอศ. ภาพหลักสำหรับคอมและมือถือ ภาพส่วนอื่น สี และข้อความหลักได้ มีขนาดภาพขั้นต่ำกำกับ ดูตัวอย่าง 2 ขนาดก่อนกดเผยแพร่ และย้อนกลับรุ่นก่อนหน้าได้ โลโก้ต้องเป็นไฟล์ต้นฉบับ PNG/WebP โปร่งใส ระบบไม่สร้างตราใหม่ ภาพแต่ละไฟล์สูงสุด 5 MB

ปุ่มส่งออกข้อมูลเจ้าหน้าที่ดาวน์โหลด `.xlsx` เป็นค่าเริ่มต้น มีตัวกรอง หัวตารางตรึง คอลัมน์กว้าง และข้อความตัดบรรทัด หากต้องการ CSV สำหรับระบบอื่นใช้ URL `/api/export?format=csv` (หรือเติม `&format=csv` หลังตัวกรองเดิม) ผู้ใช้มือถือมีแถบเมนูลัดด้านล่าง และบนคอมมีปุ่มตะกร้ากับออเดอร์ที่หัวเว็บ

## หมายเหตุเซิร์ฟเวอร์ PHP 7

การมี Apache และ PHP 7 เพียงอย่างเดียวไม่สามารถรัน Next.js นี้ได้ เว็บยังต้องมี Node.js ที่รองรับ, process ที่รันต่อเนื่อง, PostgreSQL และสิทธิ์ตั้ง Apache reverse proxy/HTTPS หรือบริการเทียบเท่า `phpMyAdmin` จัดการ MySQL/MariaDB ไม่ใช่ PostgreSQL ถ้าเครื่องวิทยาลัยให้ได้แค่ PHP 7 hosting แบบจำกัดสิทธิ์ ยังย้ายโค้ดนี้ขึ้นตรง ๆ ไม่ได้ ต้องขอบริการ Node.js/PostgreSQL หรือเลือกเครื่องโฮสต์อื่นก่อนเปิดจริง จึงยังไม่เปลี่ยนเว็บเป็น PHP เพราะยังไม่ทราบสิทธิ์การดูแลเครื่อง

สลิปสูงสุด 3 × 5 MB ต่อออเดอร์ ควรวางแผนพื้นที่รวมข้อมูลและสำรองข้อมูล เช่น 4,000 ออเดอร์ที่ใช้ครบจะเป็นภาพสลิปได้ถึงประมาณ 60 GB ก่อนนับไฟล์อื่น การเปิดจริงต้องกำหนดขนาดคำขอที่ Apache ให้รับ multipart อย่างน้อยราว 16 MB และทดสอบการสำรอง/กู้คืน
## ไฟล์ข้อมูลและภาพ

- `tmp/pgdata/`: ฐานข้อมูล PostgreSQL บนเครื่องนี้; สำรองก่อนล้างข้อมูลหรือย้ายเครื่อง
- `data/demo.json`: ข้อมูลเดิมที่นำเข้าครั้งแรก และเป็นที่เก็บสำรองสำหรับ branch `main` เท่านั้น
- `data/backups/`: สำเนาข้อมูล JSON ก่อนย้ายฐานข้อมูล
- `data/slips/`: สลิปที่อัปโหลด เก็บนอก `public/` และเข้าถึงผ่าน API ที่ตรวจสิทธิ์
- `data/site-images/`: ภาพหน้า Home ที่อัปโหลดและเสิร์ฟผ่าน API หลัง build; ต้องสำรองพร้อมฐานข้อมูล
- `public/uploads/`: ภาพสินค้าที่อัปโหลด
- `public/assets/`: ภาพตัวอย่างและภาพอ้างอิง

อย่าลบ `tmp/pgdata/`, `data/slips/` หรือ `public/uploads/` หากยังต้องใช้ข้อมูลทดลองปัจจุบัน การเปลี่ยน Git branch ไม่ย้อนฐานข้อมูลอัตโนมัติ

## Branch และการย้อนกลับ

`main` คือเดโมก่อนปรับ workflow และ PostgreSQL (commit `7786142`), `feature/customer-led-workflows-postgres` คือรุ่น workflow และ PostgreSQL และ `feature/superadmin-site-controls` คือรุ่นตั้งค่าเว็บและ UI ที่กำลังพัฒนา หากต้องการกลับไปดูหน้าตาเดิม ให้หยุดเว็บก่อนแล้วสั่ง `git switch main`; กลับมารุ่นใหม่นี้ด้วย `git switch feature/superadmin-site-controls` ข้อมูล runtime ทั้งสองแบบถูกเก็บแยกจาก Git: `main` ใช้ JSON เดิม ส่วน branch ใหม่ใช้ PostgreSQL อย่าใช้การสลับ branch แทนการสำรองฐานข้อมูล

## ขอบเขตความปลอดภัยและทางไปสู่ระบบจริง

รุ่นนี้มีรหัสผ่านแบบ hash, HTTP-only cookie, สิทธิ์บนเซิร์ฟเวอร์, สลิปนอก `public/`, ตรวจไฟล์ และการแก้คำสั่งซื้อผ่าน transaction ใน PostgreSQL เพื่อกันคำสั่งที่ชนกัน PostgreSQL ใช้ได้ทั้ง Windows และ Linux โดยเปลี่ยนค่าเชื่อมต่อฐานข้อมูลเมื่อย้ายเครื่อง

ก่อนเปิดรับเงินหรือข้อมูลจริง ต้องยืนยันราคากับบัญชีรับชำระ, เปลี่ยนรหัสผ่านสาธิต, เพิ่มการยืนยันบัญชีและ 2FA เจ้าหน้าที่, ตั้ง HTTPS/reverse proxy, ทดสอบโหลดกับผู้ใช้พร้อมกันจริง, วางแผน backup/restore, ตรวจความปลอดภัย และกำหนดวิธีจัดการสลิป/ข้อมูลส่วนบุคคล ระบบปัจจุบันยังเป็น **ข้อมูลสาธิต**; ยังไม่ได้พิสูจน์ประสิทธิภาพภายใต้โหลด 3,000–4,000 คนพร้อมกัน
